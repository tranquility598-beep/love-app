# План развертывания, автоматизации обновлений и монетизации Love

Этот план описывает этапы подготовки, запуска приложения на домене [loveapp.chat](https://loveapp.chat), настройки автоматического обновления через GitHub, сборки APK для Android и запуска встроенного маркетплейса.

---

## Этап 1: Финализация и полировка в песочнице
1. Завершить тестирование мобильного интерфейса и жестов.
2. Проверить стабильность работы аудиоплеера и новой логики перетаскивания (слайдера).
3. Добавить в `index.html` необходимые метатеги для мобильных устройств (PWA-совместимость):
   - Apple Touch Icon (иконка для iOS).
   - `apple-mobile-web-app-capable` (работа во весь экран на iOS).
   - Тематический цвет панели (`theme-color`).

---

## Этап 2: Перенос дизайна и интеграция в рабочее приложение
Так как текущие файлы в `sandbox` являются интерактивным макетом (mockup), их дизайн и логику необходимо перенести в ваше существующее работающее приложение.
1. **Анализ структуры основного приложения:** Изучить файловую структуру вашего рабочего проекта (где лежат бэкенд-роуты, шаблоны/компоненты фронтенда и стили).
2. **Перенос стилей:** Перенести CSS-переменные, темы оформления и новые стили из `sandbox/style.css` в глобальные стили вашего рабочего приложения.
3. **Обновление верстки:** Заменить старый интерфейс на новую адаптивную структуру из `sandbox/index.html` (шапки чатов, боковое меню, профили с кастомными SVG-настроениями и увлечениями, музыкальный мини-плеер).
4. **Интеграция с бэкендом (API и БД):**
   - Заменить мок-данные (`mockFriends`, `mockConversations` и т.д.) на реальные запросы к вашей базе данных.
   - Подключить WebSocket-соединение (или сокеты вашего бэкенда) для мгновенной отправки сообщений, обновления статусов и смены музыки.
   - Настроить сохранение импортированных аудиофайлов на вашем сервере (или облачном хранилище) с записью URL в профиль пользователя в БД, чтобы другие пользователи могли слышать этот трек через плеер.
5. **Проверка работоспособности:** Протестировать корректность сохранения настроек профиля и синхронизацию состояния плеера.

---

## Этап 3: Публикация в GitHub и настройка CI/CD (Автодеплой)
1. **Создание репозитория:** Создать новый приватный или публичный репозиторий на GitHub.
2. **Инициализация Git:** В папке проекта запустить:
   ```bash
   git init
   git add .
   git commit -m "feat: initial mobile release with interactive player"
   ```
3. **Пуш кода:** Связать локальную папку с GitHub и выгрузить код.
4. **Выбор хостинга (Vercel / Netlify):** 
   - Зарегистрироваться на Vercel (или Netlify) через аккаунт GitHub (это бесплатно).
   - Импортировать созданный репозиторий GitHub.
5. **Автоматизация обновлений:** 
   - При подключении репозитория к Vercel/Netlify система автоматически настраивает CI/CD.
   - **Каждый раз, когда вы делаете `git push` на GitHub, хостинг автоматически собирает новую версию сайта и обновляет её у пользователей.** Никаких ручных файлов перекидывать больше не нужно.

---

## Этап 3: Подключение домена loveapp.chat
1. В личном кабинете Vercel/Netlify в настройках проекта перейти в раздел **Domains** и добавить ваш домен `loveapp.chat`.
2. Система хостинга выдаст IP-адрес для записи `A` и адрес для записи `CNAME`.
3. **Настройка в Spaceship:**
   - Войти в панель управления доменом на Spaceship.
   - Перейти во вкладку **Advanced DNS** (или DNS Manager).
   - Удалить стандартные (парковочные) записи и добавить:
     - **Запись типа A:** Имя `@`, значение `[IP-адрес от Vercel]`
     - **Запись типа CNAME:** Имя `www`, значение `[CNAME-адрес от Vercel]`
4. **SSL-сертификат:** Хостинг автоматически выпустит бесплатный SSL (HTTPS) сертификат безопасности, как только DNS-записи обновятся (обычно от 5 минут до 2 часов).

## Этап 5: Активация PWA (Установка на экран телефона)
1. **Манифест приложения:** Создать в корне проекта файл `manifest.json`, описывающий параметры приложения (имя, иконки 192x192 и 512x512, стартовый URL, цвет темы, режим отображения `standalone` для скрытия адресной строки).
2. **Сервис-воркер:** Создать файл `service-worker.js` для кэширования статических файлов (HTML, CSS, JS, иконки). Это позволит приложению запускаться мгновенно и работать без интернета.
3. **Регистрация:** Добавить в `script.js` код регистрации сервис-воркера при загрузке страницы.

---

## Этап 6: Сборка APK для Android (без Google Play)
1. **Подключение Capacitor:** Установить Capacitor в проект для легкой обертки веб-кода в нативный:
   ```bash
   npm install @capacitor/core @capacitor/cli
   npx cap init Love "loveapp.chat" --web-dir=sandbox
   ```
2. **Добавление платформы Android:**
   ```bash
   npm install @capacitor/android
   npx cap add android
   ```
3. **Генерация APK:**
   - Открыть сгенерированную папку `android` в программе **Android Studio**.
   - Выполнить сборку релизного файла (`Build` -> `Build Bundle(s) / APK(s)` -> `Build APK(s)`).
4. **Дистрибуция:** Полученный файл `app-release.apk` залить в файловое хранилище и разместить прямую ссылку на его скачивание на самом сайте `loveapp.chat` (например, кнопка «Скачать для Android (APK)»).

## Этап 7: Запуск Маркетплейса кастомизаций (монетизация)
Маркетплейс позволит пользователям продавать свои «украшения» для профилей и чатов (уникальные темы оформления, SVG-наборы настроений, кастомные фоны, стили рамок аватаров, звуковые паки).

### 1. Архитектура базы данных
- Таблица **Users** (ID пользователя, баланс, статус лицензии продавца).
- Таблица **Products** (ID товара, автор, название, тип украшения, цена, код/файлы украшения, статус модерации).
- Таблица **Transactions** (ID операции, покупатель, продавец, сумма сделки, комиссия платформы).

### 2. Монетизация и комиссии
* **Лицензия продавца ($3 единоразово):**
  - Чтобы получить возможность выставлять свои украшения на продажу, пользователь должен активировать лицензию за $3.
  - Оплата проходит через платежный шлюз (Stripe / Stripe Billing или Crypto Pay).
* **Комиссия с продаж (20%):**
  - При покупке любого цифрового товара на маркетплейсе плата списывается с покупателя.
  - **80% стоимости** моментально перечисляется на внутренний баланс продавца.
  - **20% стоимости** удерживается как комиссия сервиса и уходит на ваш счет.

### 3. Техническая реализация платежей
- **Интеграция Stripe:** Позволяет принимать банковские карты (Visa, Mastercard) и Apple Pay/Google Pay.
- **Внутренний баланс и Выплаты:**
  - Накопленные средства (80% от продаж) хранятся на внутреннем балансе авторов.
  - Авторы могут запросить вывод средств (Payout) при достижении минимальной суммы (например, от $10). Выплаты осуществляются вами вручную или автоматически на их кошельки/карты.
- **Применение украшений:** При покупке сервер проверяет права пользователя на товар и динамически подгружает CSS/SVG-код купленного украшения в его профиль.
