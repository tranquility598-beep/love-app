# Редактор публичной страницы профиля

Живёт на `me.loveapp.chat/build`. Отдаётся как обычная статика из
`profile-page/build` (см. `server/routes/profilePublic.js`).

## Здесь намеренно нет сборки

Ни webpack, ни vite, ни шага `npm run build`. Причины:

1. **Оно должно ехать вместе с кодом.** `admin/dist` в git не лежит, и если
   релиз собрали без `npm run build` в `admin/`, сервер отдаёт 503 «панель не
   собрана». Для редактора страницы такой сценарий означал бы, что человек
   нажал в приложении «настроить страницу» и попал в пустоту. Статика в
   репозитории приезжает одним `git checkout`, ломаться там нечему.
2. **CSP всё равно запрещает лишнее.** `builderCsp()` выдаёт
   `script-src 'self'` — никаких inline-скриптов, никаких CDN. То есть JS
   обязан лежать отдельными файлами на нашем домене. Ровно то, что здесь и
   есть, только без прослойки.
3. **Размер задачи не тот.** Это панель с формой и превью, а не второе
   приложение. ES-модули (`<script type="module">`) дают нормальное разделение
   на файлы без бандлера.

Отсюда же следствие: **никаких зависимостей из npm**. Всё на том, что есть в
браузере.

## Пути

В `index.html` ссылки на ассеты **абсолютные** (`/build/app.css`), а не
относительные. Роутер отдаёт этот же index.html и на `/build`, и на
`/build/что-угодно`, так что относительный `app.css` разрешался бы то в
`/app.css`, то в `/build/app.css` — в зависимости от того, был ли слэш на
конце. Внутри JS импорты относительные: они считаются от URL модуля, а он
всегда `/build/...`.

## Превью

Превью рисуется **в том же документе, в shadow DOM**, а не в iframe: CSP
редактора содержит `frame-src 'none'`, да и сама публичная страница отдаётся с
`frame-ancestors 'none'`.

При этом ни вёрстка, ни CSS страницы здесь не переписаны: и то и другое
приходит с сервера (`POST /api/profile-page/preview`) от того же рендерера,
который отдаёт настоящую страницу. Иначе превью начало бы врать — сначала
чуть-чуть, потом заметно.

Эффекты используют общий `build/effects.js`. Браузер подключает его как
статический модуль, сервер получает ту же функцию через
`server/utils/profileEffects.js` и встраивает её в публичную страницу.
Отдельного серверного маршрута для движка нет. Плеер работает в превью
после клика, с сохранением настроенной громкости.

## Композиции и оформление

Сохранённые идентификаторы раскладок совместимы с прежними страницами:
`stack` теперь Focus (компактная страница с горизонтальной шапкой),
`card` — Studio (две колонки), `cinema` — Cover (полноэкранная обложка
и крупное имя). Разметка разделена на обложку, блок автора и содержимое;
плеер находится в потоке страницы. Статус и настроение — компактные
детали у описания, интересы — отдельные теги. Кнопка связи находится
рядом с автором, подвал содержит только служебную информацию.

Шрифты в `build/fonts/` взяты из уже включённого в Love набора.
`build/fonts.css` загружается редактором и используется серверным рендером.
Настроение преобразуется в подпись, интересы передаются только как
`{text, icon}`: идентификаторы поддокументов и сырые объекты в HTML не попадают.

Эффекты используют размер своей поверхности и время между кадрами,
останавливаются на скрытой вкладке и освобождаются при смене оформления.
На слабых устройствах снижаются плотность и частота кадров; при
`prefers-reduced-motion` анимации отключаются.

## Файлы

| Файл | Зачем |
|------|-------|
| `build/index.html` | Каркас: экран входа + две колонки редактора |
| `build/app.css` | Оформление самой панели (к странице профиля отношения не имеет) |
| `build/app.js` | Загрузка: вход, чтение данных, сборка секций |
| `build/api.js` | Токен редактора и запросы к `/api/profile-page` |
| `build/ui.js` | Мелкие помощники для DOM и уведомлений |
