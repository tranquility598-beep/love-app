# Push на Android (FCM) — сервер готов, клиент ждёт ключей

Дата: 2026-10-25. Задача: уведомления и входящие звонки на телефоне, когда
приложение закрыто.

## Коротко

Сервер уже умеет отправлять push через Firebase Cloud Messaging. Пока нет
ключа Firebase — отправка выключена и ничего не ломает (модуль молча
пропускает вызовы). Чтобы включить, нужно один раз завести проект Firebase
и положить два файла (см. ниже). После этого останется подключить Firebase
в мобильном клиенте — это следующий шаг, его делаю я.

Что уже работает без Firebase: если позвонили, пока приложение было закрыто,
и человек открывает приложение, пока звонок ещё идёт (45 с), вызов теперь
появляется — телефон сам спрашивает у сервера ожидающие звонки событием
`call:pending`.

## Оплата

FCM бесплатен. Тариф Spark (по умолчанию) не требует привязки карты, поэтому
превысить лимит и получить долг нельзя: лимитов на количество сообщений у FCM
нет. Cloud Functions (там есть платный платиновый тариф Blaze) нам не нужны —
сервер отправляет сообщения сам по HTTP v1.

## Что нужно от владельца

1. Открыть https://console.firebase.google.com → «Создать проект» (имя любое,
   например `love-app`). Google Analytics можно отключить.
2. В проекте: «Добавить приложение» → Android.
   - Имя пакета: `chat.loveapp.mobile` (ровно так, иначе push не дойдут).
   - Прозвище и SHA-1 можно не заполнять: для FCM они не нужны.
3. Скачать `google-services.json` и положить в `mobile/android/app/`.
   Этот файл не секрет, его можно держать в git.
4. Настройки проекта → «Сервисные аккаунты» → «Создать новый закрытый ключ».
   Скачается JSON — это **секрет**, в git его класть нельзя.
   На сервере (VDSina) положить, например, в `/etc/love/fcm-service-account.json`
   и добавить в окружение сервера одну из строк:
   ```
   FCM_SERVICE_ACCOUNT_FILE=/etc/love/fcm-service-account.json
   # или целиком содержимое файла:
   FCM_SERVICE_ACCOUNT={"type":"service_account", ...}
   ```
   `project_id` берётся из ключа; при необходимости его можно задать
   отдельно через `FCM_PROJECT_ID`.
5. Перезапустить сервер. Проверка: `GET /api/push/status` под своим токеном
   должен вернуть `{"configured": true, "devices": 0}` (сейчас, без ключа,
   `configured: false`).

## Что уже лежит в коде

- `server/models/PushToken.js` — токены устройств (уникальный токен, владелец,
  время последней регистрации).
- `server/services/push.js` — отправка FCM HTTP v1: ключ из
  `FCM_SERVICE_ACCOUNT` / `FCM_SERVICE_ACCOUNT_FILE`, access token Google
  (JWT RS256 через уже установленный `jsonwebtoken`, без новых зависимостей),
  кеш токена на час, удаление мёртвых токенов по `UNREGISTERED`/404.
  Сообщение уходит обычным уведомлением в канал `love_messages`, звонок —
  только данными с `priority: high` и временем жизни 45 с, чтобы клиент сам
  поднял полноэкранный вызов.
- `server/routes/push.js` — `POST /api/push/token` (регистрация),
  `DELETE /api/push/token` (выход из аккаунта), `GET /api/push/status`.
- `server/socket/socketHandler.js` — три точки отправки, только когда у
  человека нет живого соединения (иначе получилось бы двойное уведомление):
  новое сообщение в ЛС, входящий звонок, пропущенный звонок по таймауту.
- `server/tests/push.test.js` — 9 тестов без сети: ключ генерируется в тесте,
  `fetch` подменяется.

## Что осталось (делаю после ключей)

1. `mobile/pubspec.yaml`: `firebase_core`, `firebase_messaging`.
2. Инициализация Firebase и `FirebaseMessaging.instance.getToken()` после
   входа → `POST /api/push/token`; при выходе — `DELETE`.
3. Фоновый обработчик сообщений: открыть нужный диалог по `data.type=new_dm`.
4. Для звонков: `data.type=incoming_call` → полноэкранное уведомление с
   «Принять»/«Отклонить» (канал `love_calls`, fullScreenIntent). Кнопки уже
   обрабатывает `CallCenter.handleNotificationAction`.
5. Собрать APK и проверить на телефоне: закрыть приложение полностью
   (смахнуть из недавних), написать с ПК, позвонить с ПК.
6. Напомнить про агрессивные прошивки: на Xiaomi/Huawei/Honor/Samsung нужно
   вручную разрешить автозапуск и «работу в фоне», иначе система режет даже
   FCM.
