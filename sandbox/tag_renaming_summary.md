# Отчет о ревизии тегов и версий Love App

Этот документ содержит историю изменений, произведенных для ревизии версионирования проекта, перевода тегов в диапазон `1.x.x` и подготовки к выпуску обновления `2.0.0`.

---

## 1. Мотивация изменений
В процессе разработки проекта версии тегов назначались некорректно (минорные и патч-обновления ошибочно публиковались как мажорные версии `v2.x.x` - `v5.x.x`). 
Чтобы выпустить следующее крупное обновление под версией **`2.0.0`**, было принято решение перевести всю историю существующих релизов в диапазон **`1.x.x`** согласно семантическому версионированию (SemVer).

## 4. Особенности автообновления (Важно)

Поскольку автоапдейтер (`electron-updater`) сравнивает версии по правилам SemVer (`2.0.0` меньше, чем `5.2.1`):
* Пользователи, у которых на компьютерах уже установлена старая версия **`5.2.1`**, **не увидят автообновление** до версии **`2.0.0`**.
* **Решение**: На сайте будет добавлена кнопка для прямой ручной установки актуальной версии. Пользователи скачают установщик `2.0.0` поверх `5.2.1`, перейдут на новую ветку версий, и все последующие апдейты (`2.0.1`, `2.1.0` и т.д.) будут приходить им автоматически.

## 5. Как выпустить обновление 2.0.0

Когда вы будете готовы опубликовать новую версию:
1. В файле [package.json](file:///C:/Users/Aleksandr/Desktop/Love/package.json) измените значение:
   ```json
   "version": "2.0.0"
   ```
2. Запушите изменения в `main` на GitHub.
3. Создайте тег `v2.0.0` на этом коммите:
   ```bash
   git tag v2.0.0
   git push origin v2.0.0
   ```
4. Создайте и опубликуйте релиз `Love v2.0.0` на GitHub.
