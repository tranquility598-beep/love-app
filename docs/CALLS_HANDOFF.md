# Love Calls: handoff

Дата: 4 августа 2026.

## Что сделано

### Backend

- Добавлено каноническое событие `voice:media_state` с режимами `none`, `camera`, `screen`.
- Сервер проверяет, что отправивший сокет действительно находится в указанном войсе и меняет только своё состояние.
- `voice:existing_members` и `voice:members_update` всегда содержат `mediaMode`, `cameraOn`, `screenSharing`.
- Камера и демонстрация взаимоисключающие на уровне общего сервиса.
- Старые `screen:start/stop` и `camera:start/stop` проходят через тот же обработчик.
- `call:request` и `call:incoming` поддерживают `kind: audio|video`; старый клиент считается голосовым.
- Добавлены unit-тесты сериализации и переключения режимов.

### Electron / ПК

- В окне ЛС декоративные фиды заменены настоящими `<video autoplay playsinline>`.
- Создан `CallStageController`: хранит локальный и удалённые `MediaStream`, режимы медиа и участников.
- Голосовой звонок ЛС теперь остаётся сценой с двумя плитками-аватарами; камера/экран заменяют содержимое нужной плитки.
- Удалён повторный вывод тех же потоков в скрытые legacy-превью; удалённое аудио остаётся в отдельном аудиоэлементе.
- Серверный войс использует адаптивную сетку плиток. Экран можно раскрыть только кликом; автоматически фокус не перехватывается.
- Добавлена кнопка сворачивания серверной сцены обратно к чату и существующей мини-панели.
- Основной и альтернативный выбор источника экрана отправляют media-state до WebRTC renegotiation.
- Входящий вызов различает голосовой и видеозвонок.
- До выкладки нового backend клиент пробует каноническое событие и только при отсутствии ACK использует legacy-событие.

### Flutter

- ЛС и серверные войсы отправляют `camera/screen/none` до renegotiation.
- Вход в DM-комнату теперь ждёт ACK сервера, что убирает гонку `media_state` раньше `voice:join`.
- Исходящий видеозвонок отправляет `kind: video`; входящий видеозвонок сохраняет тип и запускает камеру после принятия.
- Добавлен ACK-based fallback на старые события для совместимости с текущим production до обновления backend.
- Debug APK собран и установлен на `23122PCD1G` с сохранением данных.

## Безопасное продолжение

- Не делать общий `git reset`: рабочее дерево содержит много несвязанных незакоммиченных изменений.
- Перед production отдельно просмотреть diff файлов звонков и создать именованный backup/commit.
- Сначала обновить backend, затем перезапустить PM2 и только после health/smoke включать новый APK для тестового аккаунта.
- При проблеме клиента можно вернуть предыдущий APK; при проблеме сервера вернуть предыдущий SHA. Новые клиенты временно совместимы со старым медиа-сигналингом через fallback.
